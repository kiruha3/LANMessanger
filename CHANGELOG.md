# Changelog — LAN Messenger

Версии до 0.9.1 не нумеровались; вся ранняя история собрана в блок «0.1.0».

## 0.9.8 — 2026-10-03

- Совместный сеанс RDP теперь выключен по умолчанию; включается свитчем в настройках.
- Если совместный сеанс не сработал (нет политики Shadow, нет активной сессии, старая версия у собеседника) — открывается обычный RDP, с пояснением причины.

## 0.9.7 — 2026-10-03

- Кнопка «Разрешить совместное подключение на этом ПК» в настройках: прописывает Shadow=2 в реестре через UAC, без ручной работы с regedit.

## 0.9.6 — 2026-10-03

- Теневой режим RDP (mstsc /shadow): подключение к живой сессии пользователя вместо выкидывания её на экран блокировки. Id сессии запрашивается по каналу мессенджера. Требуется политика Shadow на удалённом ПК — иначе понятная ошибка.

## 0.9.5 — 2026-10-03

- Ошибки туннеля показываются в окне: старая версия у собеседника, RDP выключен флагом, порт 3389 не отвечает. Раньше mstsc просто молча не подключался.

## 0.9.4 — 2026-10-03

- Флаг `--multi` — запуск второго экземпляра для тестов (защита от дублей обходится).

## 0.9.3 — 2026-10-03

- Свитчи вместо чекбоксов в настройках, рисуются кодом. Файл check.png удалён — для раздачи снова нужен только exe.

## 0.9.2 — 2026-10-03

- Кнопка сортировки списка: в сети сверху / по имени / по IP. Режим сохраняется. Сортировка по имени убирает перестановку строк при смене статусов.
- Галочки в чекбоксах вместо залитых квадратов.

## 0.9.1 — 2026-10-03

- Номер версии в заголовке окна и в трее.

## 0.1.0 — 2026-10-02

MVP и работа над ошибками первого дня боевого тестирования.

Добавлено:

- UDP-discovery в LAN (announce/response/bye), список узлов по IP, статусы в сети/не в сети.
- Личные чаты: TCP-кадры, подтверждение доставки, история в одном файле history.db рядом с exe.
- Постоянные соединения: канал открывает сторона, которая может достучаться, — через интернет достаточно одного проброшенного TCP 45678.
- RDP-туннель по кнопке в чате: mstsc на 127.0.0.1:3390, трафик через канал мессенджера.
- Сканер подсети (ping/ARP/hostname), живые строки по мере находки.
- Трей с уведомлениями при закрытом окне, автозапуск с Windows.
- Настройки с фичефлагами (RDP, сканер, ntfy), тёмная и светлая темы, пузыри сообщений.
- Ручное добавление узла по IP, в т.ч. белому.

Исправлено:

- Ручные пиры и разрешённые IP терялись при перезапуске — переписка через интернет умирала молча. Теперь сохраняются в settings.json.
- Дедлок при одновременном дозвоне с двух сторон: оба соединения закрывались. Решается тай-брейком по node_id.
- Дубли узла при анонсе с нескольких адресов (белый IP + VPN) — одна строка на клиента.
- Прыжки списка узлов: перерисовка только при реальных изменениях, скролл сохраняется.
- Сканер хватал виртуальные адаптеры Docker/WSL и «фантомы» из VPN — фильтр по интерфейсам со шлюзом и по ARP.
- Текст пузырей был невиден в светлой теме при тёмной теме Windows — явный цвет текста.
- Повторный запуск exe теперь закрывает зависший экземпляр и стартует сам (pid-файл + мьютекс).
- Мёртвые узлы удаляются из списка через час.
