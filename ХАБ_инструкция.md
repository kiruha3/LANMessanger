# Хаб: вид, запуск на Windows и сборка на Linux с нуля

Хаб — это тот же LAN Messenger в консольном режиме (без окон): слушает сеть,
принимает комнаты и релеит сообщения. Всё остальное (протокол, комнаты,
шифрование) — тот же код, что и в оконной версии.

## Как выглядит хаб

Консоль показывает старт и события сети (каждые 5 сек — живой список узлов):

```
Узел 'hub' запущен (udp 45677, tcp 45678). Ctrl+C — выход.
+ [online ] kirill @ 185.112.226.84:45678
+ [online ] vlasova-tv @ 176.119.18.120:45678
--- узлы ---
  [online ] kirill @ 185.112.226.84:45678
  [online ] vlasova-tv @ 176.119.18.120:45678
- [offline] vlasova-tv @ 176.119.18.120:45678
```

При остановке (Ctrl+C или kill) шлёт `bye` — у остальных статус сразу «не в сети».
Окон, иконок, уведомлений в консольном режиме нет — только лог.

## Запуск на Windows

Из папки с исходниками (или где лежит main.py), Python 3.11+:

```bat
python -u main.py --console --name hub
```

Опции (все необязательные):

| Флаг | Назначение | Дефолт |
|---|---|---|
| `--name ИМЯ` | имя узла в сети | имя пользователя ОС |
| `--udp-port N` | порт discovery | 45677 |
| `--tcp-port N` | порт канала/комнат | 45678 |
| `--peer IP:PORT` | ручной пир (если broadcast закрыт) | — |
| `--multi` | разрешить второй экземпляр | — |

Автозапуск на Windows — планировщик задач:
`Действие: pythonw -u main.py --console --name hub`, триггер «при входе в систему».

## Сборка на Linux с нуля (Ubuntu/Debian)

```bash
# 1. Зависимости
sudo apt update && sudo apt install -y git python3 python3-pip
pip3 install cryptography --break-system-packages  # для PSK-комнат

# 2. Код
sudo git clone https://github.com/kiruha3/LANMessanger.git /opt/lanmessenger

# 3. Настройки (приём из любых сетей — хаб публичный)
cat > /opt/lanmessenger/settings.json << 'EOF'
{"name": "hub", "accept_all": true, "hub_enabled": true,
 "rdp_enabled": false, "scan_enabled": false,
 "update_url": "", "update_text": "", "notify_update": false,
 "push": {"enabled": false, "port": 8087, "topic": "lanalerts"},
 "rooms": []}
EOF

# 4. Сервис systemd (автозапуск и авторестарт)
sudo tee /etc/systemd/system/lanmessenger.service << 'EOF'
[Unit]
Description=LAN Messenger hub
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/lanmessenger
ExecStart=/usr/bin/python3 -u /opt/lanmessenger/main.py --console --name hub
Restart=always
RestartSec=5
Environment=PYTHONIOENCODING=utf-8

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now lanmessenger

# 5. Файрвол
sudo ufw allow 45678/tcp   # или iptables, если ufw нет
```

Проверка:

```bash
systemctl is-active lanmessenger        # active
ss -tlnp | grep 45678                   # LISTEN
journalctl -u lanmessenger -n 20        # лог (если journald включён)
```

С клиента (оконная версия): включить «Вход в комнаты» и ввести
`комната@IP-СЕРВЕРА` — вы в общем чате.

## Обновление

```bash
cd /opt/lanmessenger && git pull && sudo systemctl restart lanmessenger
```

Данные (settings.json, history.db, hub.crt/hub.key) переживают git pull —
они в .gitignore.

## Нюансы

- Хабу нужен открытый TCP 45678 наружу (файрвол/проброс). UDP 45677 только для LAN-узлов.
- Комнаты с паролем шифрованы сквозняком (E2E): хаб видит только «не удалось расшифровать».
- Данные сервера = `history.db` хаба (комнаты без пароля там читаемы, с паролем — нет).
- Для боевого деплоя смените пароль root/заведите deploy-пользователя с SSH-ключом вместо пароля.
