# План: шифрование (TLS-канал + PSK-комнаты)

Источник: `АРХИТЕКТУРА_хаб_комнаты.md` §4. Цель: хаб-режим безопасен
в чужих сетях; хаб не читает текст сообщений.

## Шаг 0. Зависимости и каркас

- Добавить `cryptography` в зависимости (AES-GCM; stdlib его не имеет).
  В exe — +~5 МБ.
- `app/net/crypto.py`:
  - `room_key(password: str, room: str) -> bytes` — PBKDF2-HMAC-SHA256,
    соль = имя комнаты, 100 000 итераций, 32 байта.
  - `encrypt(key, plaintext: bytes) -> str` — base64(nonce12 + ct + tag16).
  - `decrypt(key, payload_b64: str) -> bytes | None` — None при чужом
    ключе/битом пакете (не падаем).
- Проверка: unit-прогон encrypt→decrypt, неверный ключ → None.

## Шаг 1. PSK-комнаты (ядро, без TLS)

- Пароль комнаты: при создании/входе (`join_room`) опционально; хранить
  локально в settings.json (комната → пароль, как есть, с пометкой).
- Ключ НЕ хранится и НЕ передаётся — выводится из пароля на каждой стороне.
- Протокол: `hub_msg` получает поля `enc: true`, `text` = base64-шифротекст.
  Релей хаба прозрачен (пересылает как есть, текст не читает).
- engine.send_room: если у комнаты есть пароль — шифровать text/img перед
  hub_msg; входящее hub_msg с `enc` — расшифровать; ключ не сошёлся —
  показать «[не удалось расшифровать — неверный пароль]» одной строкой,
  без падений.
- UI: в диалоге входа в комнату — поле «Пароль (если есть)»; при создании
  комнаты — чекбокс «задать пароль» + показ кода-приглашения
  `комната:пароль@IP-хаба` для пересылки.
- Проверка: 3 движка — комната с паролем, обмен читаем у обоих, у хаба в
  логе/памяти только base64.

## Шаг 2. TLS на канал клиент↔хаб

- hubd/хаб-клиент: опция TLS (self-signed сертификат, генерируется при
  первом старте в `hub.crt/hub.key` рядом с настройками).
- Клиент: при подключении — TLS-обёртка сокета, без верификации цепочки,
  но показ отпечатка сертификата при первом подключении (как SSH
  «known hosts» → settings.json `hub_fingerprint`).
- Совместимость: флаг `tls: true` в hello/настройках; старый хаб без TLS
  — обычный канал (предупреждение в UI, если комната с паролем всё равно
  защищена шагом 1).
- Проверка: хаб с TLS — клиенты подключаются, релей работает; openssl
  s_client показывает шифрование.

## Шаг 3. PSK для P2P-режима (опция)

- Настройка «сетевой пароль» (PSK на весь P2P-трафик между клиентами,
  кто его знает). Поле `enc` в обычном `msg`.
- Проверка: два узла с паролем — шифрованно; с разными — «неверный пароль».

## Шаг 4. Полировка и документация

- Смена пароля комнаты (re-key по updated_at, старые сообщения старой
  солью не перешифровываем — пометка «зашифровано старым ключом»).
- CHANGELOG, README (раздел безопасности), AGENTS.md.
- Критерии приёмки:
  1. Перехват трафика хаба (tcpdump на сервере) — текста сообщений нет.
  2. Неверный пароль — сообщение не читается, приложение не падает.
  3. Хаб без ключа (чужой) — видит только base64.

## Чего НЕ делаем сейчас

- PKI, сертификаты LetsEncrypt, ротация ключей, perfect forward secrecy —
  избыточно для LAN/P2P-мессенджера.
- Шифрование history.db на диске — отдельный вопрос (по требованию).
