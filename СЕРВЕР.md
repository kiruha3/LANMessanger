# Обновление хаба на сервере (194.226.124.123) 

Хаб = тот же клиент в консольном режиме, лежит в `/opt/lanmessenger` (git-клон
репозитория), запущен как systemd-сервис `lanmessenger`.

## Быстрое обновление (одна команда)

С локальной машины (Git Bash), после того как запушили новую версию в GitHub:

```bash
plink -batch -hostkey "SHA256:ioqc/CBaMwXEZFpfk7ZhIpJ/ns81Y1ZRZlz1myjMVO4" \
  -ssh -pw <пароль> root@194.226.124.123 \
  "cd /opt/lanmessenger && git pull -q && systemctl restart lanmessenger && systemctl is-active lanmessenger"
```

`active` в ответе — хаб обновлён и перезапущен.

## Проверить состояние

```bash
# статус и последние логи
plink -batch -hostkey "SHA256:ioqc/CBaMwXEZFpfk7ZhIpJ/ns81Y1ZRZlz1myjMVO4" \
  -ssh -pw <пароль> root@194.226.124.123 \
  "systemctl status lanmessenger --no-pager -l | head -15; journalctl -u lanmessenger -n 20 --no-pager"
```

## Порядок выпуска версии

1. Локально: тесты зелёные → поднять `__version__` в `app/__init__.py` → собрать exe → коммит → `git push` (+ тег при релизе).
2. На сервере: `git pull` + `systemctl restart lanmessenger` (команда выше).
3. Проверить из клиента: подключиться к комнате `test@194.226.124.123`.

## Если что-то пошло не так

```bash
# откатиться на предыдущий коммит
plink ... root@194.226.124.123 \
  "cd /opt/lanmessenger && git log --oneline -3 && git reset --hard <пред.коммит> && systemctl restart lanmessenger"
```

## Что где лежит на сервере

- Код: `/opt/lanmessenger` (git clone kiruha3/LANMessanger)
- Настройки и данные: `/opt/lanmessenger/settings.json`, `history.db` (переживают git pull — в .gitignore)
- Сервис: `/etc/systemd/system/lanmessenger.service` (Restart=always)
- Порт: TCP 45678 (ufw выключен, iptables ACCEPT)
