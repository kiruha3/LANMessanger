# LAN Messenger

P2P-мессенджер для локальной сети и прямых подключений через интернет — без серверов, регистрации и облаков. Один portable exe: скачал → запустил → работает.

![platform](https://img.shields.io/badge/platform-Windows%2010%2F11-blue)

## Возможности

- **Обнаружение участников автоматически** (UDP broadcast в LAN) — список контактов по IP
- **Личные чаты** в интерфейсе «как в Telegram» (пузыри, тёмная/светлая тема)
- **Работа через интернет**: достаточно открытого TCP-порта у одной стороны — постоянное соединение устанавливает тот, кто может достучаться, дальше оба пишут по нему
- **RDP-туннель по кнопке**: удалённый рабочий стол через канал мессенджера, без проброса портов на стороне «клиента»
- **Сканер сети**: все устройства подсети (IP, hostname, MAC), фоновые строки по мере находки
- **История переписки локально** — один файл `history.db` рядом с exe, никуда не передаётся
- **Трей + всплывающие уведомления** при закрытом окне, автозапуск с Windows
- **Фичефлаги** в настройках: RDP, сканер, push на телефон (ntfy) — можно выключить лишнее
- **Один exe** (~38 МБ), настройки в `settings.json` рядом — переносится папкой

## Быстрый старт

1. Скопируйте `LANMessenger.exe` на оба компьютера, запустите.
2. В одной LAN узлы найдут друг друга сами. Имя задаётся в поле «Моё имя».
3. Через интернет: у одной из сторон пробросьте на роутере **TCP 45678** (UDP 45677 — опционально, для статуса) и разрешите приложение в брандмауэре. Затем добавьте белый IP собеседника в поле «IP вручную». Пусть первым пишет тот, у кого порт закрыт, — дальше канал двусторонний.

### RDP

Откройте чат с узлом → кнопка **RDP** → запустится mstsc на `127.0.0.1:3390`.
На удалённом ПК должен быть включён «Удалённый рабочий стол» (Windows Pro/Enterprise).

## Порты

| Порт | Протокол | Назначение |
|---|---|---|
| 45677 | UDP | обнаружение узлов (announce/response/bye) |
| 45678 | TCP | сообщения, постоянный канал, туннели |
| 8087 | TCP | push на телефон (ntfy, опционально, выкл по умолчанию) |

Изменяются флагами `--udp-port` / `--tcp-port` (у всех участников должны совпадать).

## Настройки

Кнопка «Настройки…»:

- **Общие** — автозапуск с Windows, тёмная тема
- **Сеть** — принимать из любых сетей (VPN/белый IP)
- **Функции** — фичефлаги: RDP-туннель, сканер сети, уведомления ntfy

Сортировка списка — кнопка над списком: в сети сверху / по имени / по IP.

## Запуск из исходников

```bash
pip install PyQt6
python main.py            # GUI
python main.py --console  # консольный режим
python main.py --multi    # второй экземпляр (для тестов)
```

Сборка exe:

```bash
pip install pyinstaller
python -m PyInstaller --noconfirm --onefile --windowed --name LANMessenger main.py
# результат: dist\LANMessenger.exe
```

## Структура

```
main.py                  # вход, single-instance, CLI
app/
  core/
    engine.py            # ядро: чаты, настройки, watchdog соединений
    history.py           # SQLite-история (history.db)
    tunnel.py            # проброс портов (RDP) через канал
    push.py              # SSE push-сервер для ntfy
  net/
    protocol.py          # JSON-пакеты LANMSG/1, TCP-фрейминг
    discovery.py         # UDP discovery, реестр узлов, дедупликация
    connections.py       # постоянные TCP-соединения, keepalive
    scanner.py           # сканер подсети (ping/ARP/hostname)
  ui/
    main_window.py       # главное окно (список + чат)
    chat_window.py       # панель чата, пузыри Telegram-стиля
    settings_dialog.py   # настройки и фичефлаги
    theme.py             # светлая/тёмная тема
    switch.py            # виджет-переключатель
```

## Протокол (кратко)

- Discovery: UDP JSON `LANMSG/1` — `announce / response / bye`
- Канал: TCP, фрейминг `4 байта длины + JSON` — `hello / msg / ack / ping / stream_*`
- Туннель: кадры `stream_open / stream_open_ack / stream_data / stream_close` (данные base64)
- Фильтр входящих: только приватные IP + явно разрешённые; режим «принимать из любых сетей» — в настройках

## Замечания по безопасности

- Сообщения в канале не шифруются — для чувствительного трафика используйте доверенную сеть/VPN (шифрование в планах ТЗ).
- RDP-трафик в туннеле шифруется самой Windows (NLA).
- Приложение не отправляет ничего за пределы заданных узлов; телеметрии и облаков нет.
