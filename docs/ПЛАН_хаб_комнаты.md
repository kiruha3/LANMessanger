# План: комнаты через хаб-режим клиента (hub = тот же клиент)

Источник: `АРХИТЕКТУРА_хаб_комнаты.md` + решение «хаб — это наш же клиент
с открытым портом» (нет отдельного сервера на MVP).

## Принцип

Любой клиент с доступным портом (белый IP / LAN) может принимать комнаты.
Остальные подключаются к нему по нашему же постоянному TCP-каналу и пишут
`hub_join`. Хаб релеит `hub_msg` всем участникам комнаты. Код релея живёт
в движке (`engine.py`), отдельного сервера нет.

## Шаги

### Шаг 0. Протокол (сделано)
- `TYPES_TCP += hub_join / hub_leave / hub_msg / hub_members`
- `connections.py`: роутинг `hub_*` → `self.on_hub(pkt, pc)` (по образцу on_events).

### Шаг 1. Хаб-сторона в engine
- `self.rooms: dict[str, set[str]]` — комната → ключи каналов участников.
- Флаг `hub_enabled` (по умолчанию True), свитч в настройках «Принимать комнаты (быть хабом)».
- Обработчики:
  - `hub_join {room}` → добавить `pc.key` в комнату, разослать `hub_members` {room, members:[имена]} всем участникам; хаб сам тоже участник (его имя в members).
  - `hub_leave` / обрыв канала → убрать из комнаты, разослать `hub_members`.
  - `hub_msg {room, id, from, text|img}` → релей всем участникам, кроме отправителя; хаб показывает у себя как сообщение комнаты.
- Проверка: 3 движка локально — A и B заходят в комнату на H, обмен сообщениями, выход B → members обновился у всех.

### Шаг 2. Клиент-сторона в engine
- `join_room(hub_key, room)`: `get_or_dial` к хабу → `hub_join`; запомнить `(hub_key, room)` в `self.my_rooms`.
- `send_room(hub_key, room, text, img)` → `hub_msg` по каналу к хабу + своя копия в чат.
- Входящий `hub_msg` (мы не хаб) → чат `room:<hub_key>/<room>`, unread++, on_message_event.
- История: тот же history.db, key = `room:<hub_key>/<room>`.
- Проверка: сообщения ходят в обе стороны, переживают перезапуск в БД.

### Шаг 3. UI
- **Левая панель — дерево (QTreeWidget вместо QListWidget)**: узел-хаб —
  родительская ветка, комнаты, куда нас пустили, — вложенные под ним:
  ```
  ▼ 185.112.226.84 (kirill) — хаб
      🏠 rzhd (5)
      🏠 общая (12)
  ● vlasova-tv (10.10.0.104)
  ◌ 10.10.0.2 SERVER-FILES — нет мессенджера
  ```
  Узлы без комнат — плоские строки, как сейчас. Устройства без мессенджера —
  внизу. Сортировка (кнопка) действует на узлы верхнего уровня.
- Клик по комнате → чат справа; по хабу — личный чат с ним.
- Строка входа: поле «комната@IP-хаба» (как ручной IP) — парсим,
  add_manual_peer(ip) + join_room.
- ChatPanel: для `room:`-ключей — заголовок «имя комнаты (N участников)»,
  отправка через send_room (без node-объекта).
- Свитч «Принимать комнаты (быть хабом)» в Настройки → Функции.
- Проверка: smoke-тест UI — дерево: хаб с вложенной комнатой, сообщение в
  пузыре.

### Шаг 4. Боевой тест
- Хаб на вашем ПК (белый IP, проброс 45678 уже есть): у вас включён hub_enabled.
- vlasova-tv и Anastasia: вводят `rzhd@185.112.226.84` → все в одной комнате.
- Чек-лист: вход/выход, список участников, сообщения, картинка в комнату, переживание рестарта клиента.

### Шаг 5 (отдельно, после MVP)
- Пароль комнаты (PBKDF2-хэш у хаба).
- TLS на канал + PSK-шифрование контента (обязательно перед «чужими» сетями).
- Офлайн-история комнаты у хаба (буфер последних N сообщений, отдаёт при join).
- Linux-консольный клиент (app/net + REPL, без Qt).

## Ограничения MVP (честно)
- Без пароля: любой, кто знает адрес хаба и имя комнаты, может войти. Для теста в своей сети — ок; в интернет — только после шага 5.
- Хаб офлайн = комната недоступна (P2P при этом живёт).
- Текст в канале к хабу открытый до введения TLS/PSK.

## Оценка
Шаги 1–3: ~1 день. Шаг 4: полчаса с реальными машинами. Шаг 5: 2–3 дня.
