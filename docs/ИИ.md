# Локальный ИИ во вкладке мессенджера

Во вкладке «ИИ» LAN Messenger запускает Pi на этом компьютере. Агент читает и
меняет файлы, выполняет команды и обращается к выбранной модели через интернет
или совместимый локальный сервер. Учётная запись мессенджера или сервер TechHelper
для этого не нужны.

## Установка на Windows

1. Установите Node.js 22 LTS и Git for Windows с Git Bash.
2. Для установки Pi рядом с exe выполните из репозитория:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/install_ai_runtime.ps1
   ```

   Runtime появится в `dist/ai-runtime`. Переносите его вместе с exe. Сам Node.js
   и Git Bash должны быть установлены на компьютере. В этой сборке они не вшиты в exe.

   Альтернатива — глобальная установка:

   ```powershell
   npm install -g @mariozechner/pi-coding-agent@0.73.1
   ```

3. Откройте вкладку «ИИ» → «Подключение модели». Runtime определяется автоматически;
   если Pi лежит в другом месте, укажите папку его пакета или папку с `node_modules`.
4. Выберите провайдера, нажмите «Обновить модели», выберите модель либо введите её ID.
5. Войдите в аккаунт или введите API-ключ и отправьте задачу.

Проверена версия Pi 0.73.1. Остальные функции мессенджера работают и без Pi.
ИИ не запускается до запроса пользователя. Консольный хаб не использует Node.js/Pi.

## Аккаунт и API-ключ

В этой версии Pi поддерживает вход по аккаунту для OpenAI Codex (ChatGPT),
Anthropic и GitHub Copilot. Нажмите «Войти в аккаунт» и завершите вход на странице
провайдера в браузере. Если нужен код, URL или дополнительный ответ, поле появляется
в той же вкладке. Вход можно отменить. Доступность моделей и подписки зависит от
провайдера; успешная авторизация не гарантирует доступ к каждой модели каталога.

Для OpenAI API, Anthropic API и Google API можно ввести ключ. Для собственного
OpenAI-совместимого сервера выберите «Совместимый API», укажите адрес с `/v1`,
идентификатор модели и ключ. Сервер должен поддерживать Chat Completions с потоковой
выдачей и вызовами инструментов. Для локального сервера без проверки ключа можно
использовать непустое условное значение.

Если для провайдера уже сохранён аккаунт Pi, перед использованием API-ключа
нажмите «Выйти из аккаунта». Иначе Pi отдаёт приоритет аккаунту; приложение
проверяет этот случай и не отправляет запрос с неожиданной учётной записью.

Ключ без флажка сохранения хранится в памяти приложения и передаётся дочернему
процессу через окружение. В Windows флажок «Сохранить API-ключ» защищает ключ DPAPI
для текущей учётной записи Windows. На других системах доступен только ввод до выхода.
Поддерживается один активный профиль подключения.

## Рабочая папка и права

Папка определяется автоматически и показана над чатом:

- portable Windows exe — папка, где лежит `LANMessenger.exe`, включая запуск ярлыком;
- исходники — текущая рабочая папка в момент создания окна;
- macOS `.app` — папка, содержащая bundle приложения; новая вкладка не проходила
  отдельную сборку и живую проверку на macOS в рамках выпуска Windows 0.22.1.

Выбор каталога перед запросом не требуется. Рабочая папка не ограничивает доступ:
агент действует с правами текущего пользователя и может обращаться к другим папкам.
Приложение не повышает привилегии. Подтверждение каждого инструмента не запрашивается.

Провайдер получает текст задачи и содержимое, которое агент прочитал и передал
модели. Весь каталог автоматически не загружается. Переписка LAN и комнаты
автоматически в контекст не добавляются.

## Чат, остановка и история

Провайдер, модель, адрес API и путь Pi сохраняются автоматически при редактировании
и при полном выходе, даже без отправки задачи. Состояние сохранения видно в панели
подключения. На Windows включите «Сохранить API-ключ средствами Windows», чтобы
ключ восстанавливался после перезапуска. Снятие галочки удаляет сохранённый ключ,
оставляя введённый ключ в памяти до выхода. Без галочки ключ после выхода нужно
ввести заново.

Создайте новый чат и опишите задачу. Отправка — кнопкой, Enter или Ctrl+Enter;
Shift+Enter добавляет строку. В чате видны ответ и вызовы инструментов.
Ответы отображаются с Markdown: списками, ссылками и блоками кода. Размышления
поступают отдельным потоком, если модель и провайдер передают их через Pi;
во время выполнения блок раскрыт, после завершения его можно раскрыть вручную.
Действия отображаются компактными карточками с именем файла или командой и
состоянием выполнения. Нажмите на заголовок карточки, чтобы увидеть аргументы и
результат. Ошибки, остановка и прерывание отмечаются в карточке. Старые записи
истории также доступны. Ссылки открываются только по нажатию пользователя.
При новых сообщениях и обновлениях ответа или действий чат автоматически прокручивается вниз.
Ручное раскрытие карточки в старой истории сохраняет текущую позицию чтения.
Вывод одного инструмента ограничен последними 16 000 символами в интерфейсе;
контекстом модели управляет сама сессия Pi.

Представление ленты и обработка событий адаптированы из [bb](https://github.com/get-bb/bb)
на PyQt. Уведомление MIT: `THIRD_PARTY_NOTICES.md`, полный текст: `licenses/bb-MIT.txt`
и раздел лицензий во вкладке «Помощь». Веб-движок для этого не требуется.

Кнопка «Стоп» отменяет текущую задачу. Новая отправка доступна после завершения
остановки; если Pi не отвечает, процесс завершается. Сворачивание в трей сохраняет
работу агента, полный выход из приложения останавливает его процесс.

История ИИ находится отдельно от LAN-переписки в `ai-data/state.json`, сессии —
в `ai-data/sessions`. Для каждой беседы используется отдельная сессия, даже если
рабочая папка одна. Перед следующим запросом интерфейс сверяет историю с Pi.
После аварии прежняя команда автоматически не повторяется. Если сессия потеряна,
чат показывает сообщение о новом контексте. Если приложение перенесено в другую
папку, прежний чат остаётся доступен для чтения; для работы создайте новый чат.

Автоматические повторы и сжатие контекста Pi в первой версии отключены, чтобы
окончание ответа не запускало продолжение после снятия состояния «Выполняется».
При ошибке повторите запрос явно, при исчерпании контекста начните новый чат.

Pi хранит OAuth-токены в своём `ai-data/pi/auth.json`; обновление токенов выполняет
Pi. DPAPI-файл ключа расположен в `ai-data/api-key.dpapi`. Не передавайте каталог
с подключёнными аккаунтами другим людям.

## Проверка и сборка

```powershell
py -3.11 scripts/run_tests.py
powershell -ExecutionPolicy Bypass -File scripts/build_windows.ps1
```

`test_ai.py` проверяет данные, DPAPI и RPC-жизненный цикл, `test_ai_ui.py` — интерфейс,
`test_ai_pi.py` — настоящий Pi с локальным тестовым API и созданием файла инструментом.
Последний тест пропускается, если Pi не установлен; успешное выполнение этого теста
не является проверкой реального провайдера или OAuth-входа.
