# Локальный ИИ во вкладке мессенджера

Во вкладке «ИИ» LAN Messenger запускает Pi на этом компьютере. Агент читает и
меняет файлы, выполняет команды и обращается к выбранной модели через интернет
или совместимый локальный сервер. Учётная запись мессенджера или сервер TechHelper
для этого не нужны.

## Установка на Windows

1. Получите `LANMessenger.exe`, откройте вкладку «ИИ». Если компонентов нет,
   нажмите шестерёнку рядом с моделью, затем **«Установить компоненты ИИ»**. Приложение загрузит Node.js 22.23.5,
   Git Bash 2.56.1, ripgrep 15.2.0, fd 10.5.2 и Pi 0.73.1 из официальных источников.
   Нужен интернет. Автоустановка доступна на Windows x64; команды в терминале,
   права администратора и перезапуск мессенджера не требуются.
2. Дождитесь окончания установки. Виден прогресс; можно отменить и повторить.
   Файлы проверяются по закреплённым SHA256, Pi устанавливается через приватный npm
   без install scripts и глобальных пакетов. Готовая установка активируется только
   после проверки. Компоненты сохраняются в
   `%LOCALAPPDATA%/LANMessenger/ai-runtime/pi-0.73.1-node22-v1` для текущего
   пользователя Windows. Системный PATH не меняется. На другом ПК их нужно
   установить заново; ключи и история в этот каталог не копируются.
   В exe включён публичный набор корневых сертификатов; Windows проверяет цепочки
   сертификатов через системное хранилище, в том числе доверенные сертификаты
   организации. Приватные Node.js и npm также используют доверие Windows.
   Проверка HTTPS и SHA256 остаётся включённой. При ошибке сертификата проверьте
   дату и время; сертификат используемого HTTPS-прокси должен быть доверенным в Windows.
3. Нажмите шестерёнку рядом с моделью внизу чата. Выберите аккаунт или нажмите
   «Добавить аккаунт». Runtime определяется автоматически;
   если Pi лежит в другом месте, укажите папку его пакета или папку с `node_modules`.
4. Выберите провайдера, войдите в аккаунт или введите API-ключ.
5. Нажмите «Загрузить модели» в настройках подключения, выберите модель справа
   внизу поля сообщения либо введите её ID и отправьте задачу.

Проверена версия Pi 0.73.1. Остальные функции мессенджера работают и без Pi.
После установки сообщения не отправляются автоматически. Введённый запрос остаётся
в поле ввода. Существующие установки Node/Pi/Git Bash продолжают поддерживаться;
для разработчиков остаётся `scripts/install_ai_runtime.ps1` и глобальная установка
`npm install -g @mariozechner/pi-coding-agent@0.73.1` при наличии Node и Git Bash.
ИИ не запускается до запроса пользователя. Консольный хаб не использует Node.js/Pi.

## Пояснения и инструкции агента

В настройках под шестерёнкой доступны два режима: **«С пояснениями»** (по умолчанию) — короткие
пояснения перед действиями и между этапами; **«Без пояснений»** — выполнение
без промежуточных комментариев, с кратким итогом. Это инструкция модели,
а не скрытие сообщений: полученные текст, размышления и карточки инструментов
показываются в обоих режимах. Конкретный API может буферизовать поток или не
передавать размышления. Интерфейс перерисовывает полученный поток примерно раз
в 50 мс, не дожидаясь окончания всех команд.

Кнопка **«Инструкция…»** открывает текст выбранного режима. Можно сохранить
свои указания, отменить редактирование или вернуть стандартный текст. Лимит —
12000 символов; поле прокручивается, кнопки остаются видимыми. Сохраняются
обе инструкции и выбранный режим. Изменения применяются к следующей задаче,
включая продолжение существующего чата; во время задачи, входа или установки
редактор и переключатель недоступны. Пустая инструкция не добавляет указаний.
Технически выбранный текст передаётся Pi через `--append-system-prompt`.

## Аккаунт и API-ключ

В списке «Аккаунт» в настройках под шестерёнкой можно хранить несколько именованных подключений, в том числе
два аккаунта одного провайдера. «Добавить аккаунт» создаёт пустое подключение,
«Переименовать» меняет его название. Каждый аккаунт сохраняет свой провайдер,
URL, модель, загруженный каталог, уровень размышлений, инструкции и отдельные
ключи/OAuth-токены. Во время задачи, входа или установки переключение недоступно.
Прежние настройки автоматически становятся аккаунтом «Основной»; существующие
файлы ключей и сессий остаются на месте. Каждый чат запоминает свой аккаунт и
последнюю выбранную модель, даже если у нескольких чатов один аккаунт.
При переходе между чатами и после перезапуска выбор восстанавливается.
Новый чат наследует текущий выбор. Старые чаты без сохранённого выбора
восстанавливают аккаунт и модель последнего запроса, если эти данные есть;
иначе запоминают текущий выбор при первом открытии после обновления.

Чаты могут работать параллельно. Переключайтесь в списке или создавайте новый
чат во время задачи: прежний процесс, очередь генерации и ответы остаются в
исходной переписке. Пометка «работает» видна в списке; квадрат остановки
действует только на открытый чат. Черновики и вложения до отправки независимы
между открытыми чатами и хранятся в памяти до выхода из приложения.

Текстовый агент получает инструменты `generate_image`, `list_image_models`, `list_chats` и `read_chat`.
Например: «Нарисуй рыжего кота-космонавта через AI Horde». Агент подготовит
описание, создаст отдельный дочерний чат в том же проекте и вернёт картинку в
исходный чат, сохранив его текстовую модель. Без указанного аккаунта используется
настроенное подключение инструмента, изначально бесплатный Horde. Для другого сервиса явно укажите название аккаунта или ID и,
при необходимости, точный ID модели изображений. Ключи не передаются текстовой
модели. При остановке исходной задачи отменяются все её ожидающие генерации;
остальные чаты продолжают работать. После обрыва или аварийного перезапуска очередь Horde можно
получить в дочернем чате без повторной генерации; результат попадёт и в исходный.

Horde возвращает агенту очередь до готовности картинки. В ответе `generate_image`
есть ID дочернего чата, состояние `queued`/`processing`, место в очереди,
`queue.estimated_wait_seconds`, прошедшее время и момент проверки. Агент использует
`get_image_status` для повторной проверки (по умолчанию через 5 секунд; параметр
`wait_seconds` — задержка проверки, а не лимит генерации). Готовые ответы содержат
картинку; промежуточные не считаются готовым результатом. `cancel_image_generation`
отменяет только картинки текущего исходного чата. Агент сравнивает оценку с вашим
условием, например «очередь больше 100 секунд — отмени», и не придумывает лимит сам.
Оценка сервиса может меняться; сохранённая очередь помечается как `saved` с возрастом
данных. `wait_for_result=true` позволяет явно ждать итог без промежуточной очереди.

### Вопрос другому текстовому агенту

По вашей просьбе `ask_agent` отправляет вопрос в существующий свободный ИИ-чат
(`chat_id` из `list_chats`) или создаёт видимый новый чат с выбранными аккаунтом и
моделью. `list_agent_models` возвращает настроенные текстовые аккаунты и сохранённые
ID моделей без ключей. В существующем чате сохраняются его история, модель и папка;
новый использует папку исходного чата. Получатель имеет обычные возможности агента,
включая файлы и команды в рабочей папке. Вопрос отмечен именем исходного чата.
Ответ и ID беседы возвращаются вызывающему агенту; ответ другого агента считается
данными, а не новой пользовательской инструкцией.

Занятый чат, обращение к себе или чат с неотправленным черновиком отклоняются сразу.
Поддерживается до трёх вопросов одновременно и до двух уровней вложенности; встречные
вопросы в ожидающий исходный чат не создают циклического ожидания. Ожидание ответа —
300 секунд по умолчанию, `timeout_seconds` допускает 5–900 секунд. Остановка исходной
задачи отменяет её запросы и останавливает запущенных получателей; чужие задачи
продолжают работать. При выходе запросы прерываются, автоматически не повторяются.

Чтобы сравнить разные модели, напишите, например: «Нарисуй кота через AI Horde
параллельно в Dreamshaper и Flat-2D Animerge». Агент передаёт их точные ID в
`generate_image.models` (до четырёх разных моделей); отдельные вызовы
`generate_image` в одном ответе агента также выполняются параллельно.
Запросы отправляются без ожидания результата предыдущей модели.
Для Horde отправка соблюдает ограничение частоты: новые POST идут с интервалом
не менее 550 мс для всего приложения. Это не ожидание готовности другой картинки:
после отправки у каждой модели своё задание и очередь. Внешняя нагрузка, лимиты
ключа или IP всё ещё могут привести к ответу 429; повторной отправки автоматически нет.
Каждая генерация имеет собственную очередь сервиса и дочерний чат;
картинка с названием модели появляется в исходном чате по мере готовности.
Ошибка или остановка одного дочернего чата не отменяет остальные генерации.
Одинаковая модель того же аккаунта повторно не запускается, пока ещё рисует.
Сам текстовый агент продолжает ответ после завершения всех вызовов инструмента.
Лимиты сервиса могут ограничивать число принятых одновременных запросов.

В настройках каждого **текстового аккаунта** есть раздел **«Инструмент image gen»**.
В **«image gen — аккаунт»** выберите именованное подключение картинок: AI Horde,
Cloudflare или совместимый Images API. Его провайдер, URL, ключ и каталог моделей
редактируются через основной список «Аккаунт»; новое подключение создаётся кнопкой
«Добавить аккаунт». В **«image gen — модель»** выберите или введите ID модели;
пустое поле использует текущую модель аккаунта картинок. Настройка независима у
разных текстовых аккаунтов и сохраняется после перезапуска. По умолчанию остаётся
бесплатный AI Horde. Если выбранная модель или провайдер перестали работать,
переключите эти поля: следующий запрос агента использует новые настройки.
Изменение подключения картинок также обновляет инструмент в существующем чате
при следующем запросе; уже отправленные задания продолжают использовать прежние
настройки. При ошибке сервис автоматически не меняется. Если настроенный аккаунт
недоступен, инструмент сообщает, где выбрать другой, без скрытого перехода на Horde.

На вопрос «Какие модели картинок доступны?» агент вызывает `list_image_models`
у выбранного аккаунта инструмента. В AI Horde список включает модели с активными
исполнителями; в совместимом Images API сохраняются признаки доступности и причины
ограничений, если сервис их возвращает. Результат содержит точные ID, источник
каталога, число записей; доступны фильтр по ID и страницы до 200 моделей.
Если сервер недоступен, сохранённый каталог явно отмечается как возможный устаревший.
Для Cloudflare показывается поддерживаемая приложением FLUX.1 Schnell с указанием,
что доступ и квота проверяются при генерации. Каталог сам не запускает генерацию
и не передаёт ключ текстовой модели. Название модели не гарантирует качество
или поддержку определённого стиля.

В списке чатов пульсирует небольшой индикатор работающей задачи. Новый результат
в фоновом чате подсвечивается с пометкой «готово», ошибка — с пометкой «ошибка».
После открытия отметка снимается; неактивные чаты без новых результатов серые.
Непросмотренные результаты сохраняют подсветку после перезапуска.

По запросу «Найди чат … и прочитай его» агент может искать локальные ИИ-чаты и
получать последние 1–50 сообщений выбранной переписки и до четырёх картинок.
Список ограничен 50 чатами, длинные сообщения сокращаются. Эти инструменты
не читают личные чаты и комнаты LAN Messenger. Выбранные сообщения отправляются
провайдеру текущего агента как контекст задачи.

Вставьте картинку через **Ctrl+V**, перетащите файл в поле сообщения или нажмите
**«+»**. Поддерживаются PNG, JPEG и WebP: до четырёх вложений по 24 МиБ и 32 Мп.
До отправки можно убрать вложение крестиком. Оригиналы остаются в локальной
истории; модель получает PNG с длинной стороной не более 1024 пикселей.
Изображения также передаются агенту после генерации. Совместимый API теперь
объявляет поддержку изображений, чтобы Pi не удалял их из запроса. Выбранные
модель и сервер должны поддерживать vision; фактическую доступность проверяет
API. У встроенных провайдеров учитывается каталог возможностей модели.

В этой версии Pi поддерживает вход по аккаунту для OpenAI Codex (ChatGPT),
Anthropic и GitHub Copilot. Нажмите «Войти в аккаунт» и завершите вход на странице
провайдера в браузере. Если нужен код, URL или дополнительный ответ, поле появляется
в окне настроек. Вход можно отменить. Доступность моделей и подписки зависит от
провайдера; успешная авторизация не гарантирует доступ к каждой модели каталога.

Для OpenAI API, Anthropic API и Google API можно ввести ключ. Для собственного
OpenAI-совместимого сервера выберите «Совместимый API», укажите URL с `/v1`
и свой API-ключ. Нажмите «Загрузить модели», затем выберите точный ID или введите
его вручную. Сервер должен поддерживать Chat Completions с потоковой
выдачей и вызовами инструментов. Для локального сервера без проверки ключа можно
использовать непустое условное значение.

Для совместимого API список загружается асинхронным GET `<URL>/models` с ключом
в заголовке `Authorization: Bearer`. Поддерживается ответ `data[].id`, группы —
из `owned_by`. Запрос выполняется только по кнопке; смена URL, ключа или провайдера
отменяет загрузку и очищает прежний список, сохраняя введённый ID. Таймаут — 15 секунд,
предел ответа — 2 МиБ. Перенаправления не выполняются. Если сервер не предоставляет
список или вернул ошибку, модель можно ввести вручную. URL должен быть HTTP(S),
без логина, параметров и фрагмента. Для встроенных провайдеров используется каталог Pi.

## Подсказка и справочник в новом чате

До первого пользовательского сообщения сверху чата показаны шаги настройки и кнопка
«Настроить подключение». Ниже — раскрываемые разделы OpenAI, Anthropic, Google,
Google — изображения и xAI. Они используют общую прокрутку чата. Блок возвращается
в каждом новом пустом чате; в историю и контекст модели он не добавляется.

Справочник содержит 28 моделей из предоставленного пользователем
`catalog-tariffs.xlsx`, снимок от 2026-11-13. Цены указаны в рублях за миллион
токенов: вход, кеш и выход; нулевые значения сохранены. Это цены из этого файла,
а не автоматически обновляемый официальный прайс. Ориентиры по применению помогают
выбрать кандидатов для проверки на своей задаче и не гарантируют результат.
Названия в справочнике не считаются точными API ID: доступные ID получайте из
своего подключения. Для генерации изображений выберите отдельное подключение
картинок, описанное ниже.

## Картинки в чате

Базовая конфигурация уже содержит **«Картинки бесплатно — AI Horde»** с моделью
**Dreamshaper**. Она добавляется и при обновлении старой конфигурации. В новом
чате нажмите **«Нарисовать бесплатно — AI Horde»**: подключение и модель выбираются
сразу, остаётся написать описание. Регистрация, ключ, установка Pi и загрузка
каталога не нужны. Кнопка не отправляет запрос сама. Выбор сохраняется после
выхода. Если подключение Horde уже есть, используется оно, без дубля; его имя,
модель и личный ключ сохраняются. Пустая модель дополняется Dreamshaper.
Прежний выбранный аккаунт при обновлении не переключается автоматически.
Наличие готовой настройки не гарантирует наличие свободных добровольцев:
действуют очередь, ограничения анонимных запросов и доступность сервиса.

Под шестерёнкой добавьте отдельный аккаунт, чтобы сохранить текстовую модель
и её ключ, если нужно другое подключение. Затем выберите провайдера:

- **AI Horde — бесплатные картинки**: аккаунт и ключ необязательны. Нажмите
  «Загрузить модели» для списка моделей с активными исполнителями; начальный
  вариант — `Dreamshaper`. Опишите картинку, лучше на английском, и отправьте.
  Запрос создаёт одну картинку 512×512, 20 шагов. В чате показаны очередь и оценка
  ожидания от сервиса; это не гарантия срока. Есть ограничения анонимного доступа.
  Запрос обрабатывают компьютеры добровольцев. Документация API предупреждает,
  что анонимные изображения могут передаваться в открытый датасет.
- **Cloudflare — картинки, бесплатная квота**: зарегистрируйте свой аккаунт
  Cloudflare, скопируйте Account ID и создайте API-токен с правом Workers AI Read
  для этого аккаунта. В настройках мессенджера укажите их в полях Account ID и
  API-ключа. Используется `@cf/black-forest-labs/flux-1-schnell`, 4 шага, описание
  до 2048 символов. Workers Free даёт 10 000 neurons в сутки; при превышении
  операции отклоняются. На платном тарифе Cloudflare действуют условия оплаты
  превышения. Мессенджер не создаёт токен и не меняет тариф. Кнопка моделей
  показывает модель из документации; доступ проверяется при запросе.
- **Совместимый API — картинки**: задайте базовый URL, например
  `https://api.provod.ai/v1`, собственный ключ и ID модели изображений. Список
  запрашивается через `<URL>/images/models`, генерация — POST
  `<URL>/images/generations` с `n=1`, `response_format=b64_json`. Поддерживаются
  base64 и ссылка на PNG/JPEG/WebP. Недоступные модели отмечаются в каталоге;
  `FIRST_TOP_UP_REQUIRED` означает требование первого пополнения у провайдера.
  Текстовый Chat Completions и видеомодели для этого режима не подходят.

Готовое изображение показывается в ленте, оригинал сохраняется в
`ai-data/images/<chat-id>/`. Кнопки «Открыть», «Копировать картинку» и
«Сохранить как…» работают с сохранённым файлом. После повторного открытия чата
он загружается локально. Автоматическая загрузка картинок из Markdown-ответов
агента по-прежнему отключена; встроенный просмотр показывает только сохранённые
результаты генерации в папке изображений ИИ. При переносе истории переносите
также изображения; сохранённые абсолютные пути потребуют прежнего расположения.
Предел одного изображения — 24 МиБ и 32 мегапикселя. Генерация не читает файлы
проекта и не запускает Pi; каждый запрос использует только новое описание,
без контекста предыдущих картинок и без редактирования референсов.

Horde возвращает ID задания, который сохраняется до опроса результата.
После обрыва или аварийного перезапуска нажмите «Получить результат генерации» — это GET
существующего задания, без повторного POST. Пока оно сохранено, новая отправка
в том же чате не создаёт дубль. Квадрат остановки прерывает ожидание и отправляет
Horde запрос отмены; начатая работа может завершиться. Для синхронного Images API
остановка соединения не доказывает отмену работы на сервере. Автоповторов нет.
При штатном полном выходе отмена отправляется для всех сохранённых и активных
заданий Horde, включая дочерние чаты. Приложение до пяти секунд ждёт подтверждений
параллельно. Если выход начался во время отправки, оно старается получить ID и
отменить новое задание в тот же срок. Подтверждённое задание помечается остановленным;
при ошибке или таймауте ID остаётся доступным для проверки, поскольку сервис мог
продолжить работу. У синхронных Images API нет общей команды отмены. Аварийное
завершение процесса не гарантирует отправку отмены.

Условия проверены 18.11.2026: [AI Horde](https://aihorde.net/docs/image/),
[API Horde](https://aihorde.net/api/),
[Cloudflare: квота](https://developers.cloudflare.com/workers-ai/platform/pricing/),
[Cloudflare: FLUX](https://developers.cloudflare.com/workers-ai/models/flux-1-schnell/),
[Provod: Images API](https://provod.ai/ru/docs/images).

Если для провайдера уже сохранён аккаунт Pi, перед использованием API-ключа
нажмите «Выйти из аккаунта». Иначе Pi отдаёт приоритет аккаунту; приложение
проверяет этот случай и не отправляет запрос с неожиданной учётной записью.

Ключ без флажка сохранения хранится в памяти приложения и передаётся дочернему
процессу через окружение. В Windows флажок «Сохранить API-ключ» защищает ключ DPAPI
для текущей учётной записи Windows. На других системах доступен только ввод до выхода.
Без флажка ключ остаётся в памяти своего аккаунта до выхода из приложения.
Очистка поля удаляет сохранённый ключ даже при включённом флажке. Ключи провайдеров
из окружения запуска не подхватываются: используется явно выбранное подключение.

Для OpenAI API, Google API и «Совместимого API» кнопка «Отключить API-ключ»
очищает поле ключа, снимает галочку сохранения и удаляет сохранённую копию ключа.
Pi для этого не требуется. URL, модель и история остаются; для следующего запроса
нужно заново ввести ключ. Во время задачи сначала нажмите «Остановить агента» и дождитесь остановки.

«Выйти из аккаунта» относится к локальному входу Pi у провайдеров с OAuth и не
завершает браузерную сессию на сайте провайдера. Подтверждение выхода остаётся
видимым после обновления моделей. У Anthropic есть отдельные кнопки выхода из
аккаунта и отключения API-ключа: выход из аккаунта не очищает введённый ключ.

## Уровень размышлений

В панели подключения есть «Размышления»: авто, выключены, минимальный, низкий,
средний, высокий и очень высокий. Выбор сохраняется и применяется к следующей
задаче. Pi получает уровни `off`, `minimal`, `low`, `medium`, `high`, `xhigh`;
для встроенных моделей он ограничивает выбор поддерживаемыми уровнями. После
запуска в панели виден фактический уровень Pi и отличие от запрошенного, если оно есть.

Для «Совместимого API» явный выбор включает отправку `reasoning_effort` в Chat
Completions: «Очень высокий» — `xhigh`, «Выключены» — `none`. URL/ключ и список
`/models` не сообщают стандартным способом поддержку этих параметров: сервер может
вернуть ошибку. В этом случае выберите поддерживаемый уровень или «Авто».
В «Авто» для совместимого API приложение не добавляет параметр размышлений;
для встроенного провайдера используется настройка модели/сессии Pi.
Высокий уровень может увеличить время и стоимость; он не гарантирует качество ответа
или показ самого текста размышлений.

## Рабочая папка и права

Первый чат получает папку приложения автоматически:

- portable Windows exe — папка, где лежит `LANMessenger.exe`, включая запуск ярлыком;
- исходники — текущая рабочая папка в момент создания окна;
- macOS `.app` — папка, содержащая bundle приложения; новая вкладка не проходила
  отдельную сборку и живую проверку на macOS в рамках выпуска Windows 0.22.1.

Чтобы работать с другим проектом, нажмите **«Добавить папку…»** слева,
путь папки внизу поля сообщения или **«Выбрать папку…»** в настройках ИИ.
Выбор существующей папки открывает её последний созданный чат, новой папки —
создаёт первый чат проекта. Слева папки раскрываются в списки чатов;
число рядом с названием — количество чатов. Полный путь виден при наведении.
**«Новый чат»** создаёт отдельную сессию в выбранном проекте.
Выбор чата переключает рабочую директорию Pi на сохранённую папку этого чата.
Последний открытый чат и его папка восстанавливаются после перезапуска.
Во время задачи, входа или установки смена проекта недоступна.
Если папка удалена или диск отключён, история открывается для чтения;
для работы выберите существующий проект. Папка чата не меняется при переносе exe.

Рабочая папка не ограничивает доступ:
агент действует с правами текущего пользователя и может обращаться к другим папкам.
Приложение не повышает привилегии. Подтверждение каждого инструмента не запрашивается.

Провайдер получает текст задачи и содержимое, которое агент прочитал и передал
модели. Весь каталог автоматически не загружается. Переписка LAN и комнаты
автоматически в контекст не добавляются.

## Чат, остановка и история

Провайдер, модель, адрес API и путь Pi сохраняются автоматически при редактировании
и при полном выходе, даже без отправки задачи. Состояние сохранения видно в панели
подключения. На Windows включите «Сохранить API-ключ средствами Windows», чтобы
ключ восстанавливался после перезапуска. Снятие галочки удаляет сохранённый ключ,
оставляя введённый ключ в памяти до выхода. Без галочки ключ после выхода нужно
ввести заново.

Создайте новый чат и опишите задачу. Отправка — кнопкой, Enter или Ctrl+Enter;
Shift+Enter добавляет строку. В чате видны ответ и вызовы инструментов.
Рабочая папка показана внизу поля сообщения рядом с «Полный доступ».
Длинный путь сокращается; наведите курсор, чтобы увидеть полный путь.
Рядом с моделью расположена шестерёнка **«Настройки ИИ»**: аккаунты, провайдер,
URL, ключ, загрузка и выбор моделей, размышления, инструкции и компоненты ИИ.
Модель в настройках и внизу чата синхронизирована. Настройки сохраняются
автоматически, закрытие окна не отменяет уже внесённые изменения.
Поле ввода начинается с одной строки, растёт при переносах и наборе текста до
шести строк, затем прокручивается внутри. Выбор модели расположен справа внизу
общего поля сообщения. Во время работы в ленте показаны текущее действие по
событиям Pi (ожидание модели, размышления, чтение файла, команда, ответ) и
квадрат остановки вместо стрелки отправки. Отмена запуска не отправляет запрос; отмена задачи ждёт
подтверждения остановки и при зависании завершает Pi.
Ответы отображаются с Markdown: списками, ссылками и блоками кода. Размышления
поступают отдельным потоком, если модель и провайдер передают их через Pi;
во время выполнения блок раскрыт, после завершения его можно раскрыть вручную.
Действия отображаются компактными карточками с именем файла или командой и
состоянием выполнения. Нажмите на заголовок карточки, чтобы увидеть аргументы и
результат. Ошибки, остановка и прерывание отмечаются в карточке. Старые записи
истории также доступны. Ссылки открываются только по нажатию пользователя.
У раскрытых карточек нет собственной полосы прокрутки: используется общая
прокрутка чата. Концевые пробелы и пустые строки не увеличивают высоту сообщения;
в истории сохраняется исходный текст.
При новых сообщениях и обновлениях ответа или действий чат автоматически прокручивается вниз.
Ручное раскрытие карточки в старой истории сохраняет текущую позицию чтения.
Вывод одного инструмента ограничен последними 16 000 символами в интерфейсе;
контекстом модели управляет сама сессия Pi.

Представление ленты и обработка событий адаптированы из [bb](https://github.com/get-bb/bb)
на PyQt. Уведомление MIT: `THIRD_PARTY_NOTICES.md`, полный текст: `licenses/bb-MIT.txt`
и раздел лицензий во вкладке «Помощь». Веб-движок для этого не требуется.

Кнопка «Остановить агента» отменяет текущую задачу. Новая отправка доступна после завершения
остановки; если Pi не отвечает, процесс завершается. Сворачивание в трей сохраняет
работу агента, полный выход из приложения останавливает его процесс.
Внутри папок чаты отсортированы по последнему сообщению или результату: свежие
сверху, давние внизу. Время последней активности сохраняется в истории; простое
открытие чата не меняет порядок. У старой истории без времени сохраняется прежний
относительный порядок до следующего сообщения.
Правый клик по чату → «Закрепить чат» поднимает его выше незакреплённых внутри
папки; «Открепить чат» возвращает сортировку по активности. Между закреплёнными
также действует порядок последних сообщений. Закрепление сохраняется после запуска,
не меняет выбранный чат и не останавливает его работу.

Неожиданные исключения обработчиков ИИ прерывают соответствующую задачу и видны
в её истории. Traceback сохраняется в `ai-data/errors.log` с удалёнными ключами
подключений. Это локальная диагностика; она не отправляется автоматически.

История ИИ находится отдельно от LAN-переписки в `ai-data/state.json`, сессии —
в `ai-data/sessions`. Для каждой беседы используется отдельная сессия, даже если
рабочая папка одна. Перед следующим запросом интерфейс сверяет историю с Pi.
После аварии прежняя команда автоматически не повторяется. Если сессия потеряна,
переписка остаётся в ленте с сообщением о новом контексте; агент не получает
потерянный контекст автоматически. Ошибка провайдера сохраняет статус ошибки,
а не успешного завершения.

При недоступной модели интерфейс предлагает нажать шестерёнку, выбрать аккаунт,
нажать «Загрузить модели» и выбрать доступный ID. Есть кнопка **«Открыть настройки ИИ»**.
Для ошибки ключа или входа подсказка предлагает проверить ключ либо войти заново;
для ошибки доступа — проверить права на модель, для сетевой ошибки — URL и сервер.
Исходная причина остаётся в сообщении. После исправления отправьте запрос самостоятельно.

Автоматические повторы и сжатие контекста Pi в первой версии отключены, чтобы
окончание ответа не запускало продолжение после снятия состояния «Выполняется».
При ошибке повторите запрос явно, при исчерпании контекста начните новый чат.

Pi хранит OAuth-токены «Основного» в `ai-data/pi/auth.json`, его DPAPI-ключ —
в `ai-data/api-key.dpapi`. Другие аккаунты используют отдельные каталоги
`ai-data/profiles/<id>/pi/auth.json` и `ai-data/profiles/<id>/api-key.dpapi`.
Обновление OAuth-токенов выполняет Pi. Не передавайте каталог с подключёнными
аккаунтами другим людям.

Агент запускается через SDK Pi с настройками приложения: пакеты из `.pi/settings.json`
рабочей папки не устанавливаются, автоматическая загрузка расширений, skills,
шаблонов и тем отключена. Текстовый контекст AGENTS.md/CLAUDE.md по-прежнему может
использоваться Pi. Это не изоляция команд: агент работает с правами пользователя.
HTTP(S)_PROXY и NO_PROXY продолжают поддерживаться.

## Проверка и сборка

Для проверки изменений интерфейса сборка не нужна: `py -3.11 main.py` запускает
приложение из исходников, рабочие данные используются из текущей папки. Чтобы
открыть данные рядом с прежним exe, выполните из корня репозитория:

```powershell
Set-Location dist
py -3.11 ../main.py
```

Перед тестами и сборкой:

```powershell
py -3.11 scripts/run_tests.py
powershell -ExecutionPolicy Bypass -File scripts/build_windows.ps1
```

`test_ai.py` проверяет данные, DPAPI и RPC-жизненный цикл,
`test_ai_profiles.py` — независимые аккаунты, ключи, модели и восстановление истории,
`test_ai_ui.py` — интерфейс,
`test_ai_pi.py` — настоящий Pi с локальным тестовым API и созданием файла инструментом.
Последний тест пропускается, если Pi не установлен; успешное выполнение этого теста
не является проверкой реального провайдера или OAuth-входа.
