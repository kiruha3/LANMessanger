# bb AI Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Adapt bb's streamed conversation and expandable activity presentation to the native PyQt AI tab.

**Architecture:** A pure Python Pi timeline projection owns ordered text, thinking and tool entries. A native scroll area maintains stable row widgets and updates only changed rows. AITab continues to own sessions, connection settings and Pi lifecycle.

**Tech Stack:** Python 3.11, PyQt6, installed Pi 0.73.1; no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-13-bb-ai-chat-design.md` (approved by user: «Да, делай на PyQt»).

## Global Constraints

- Keep local Pi, current provider authentication, application folder and existing history.
- Enter sends; Shift+Enter inserts a newline; new content scrolls to bottom.
- No push. Every behavior change updates CHANGELOG and affected documentation.
- Every exe build increments version and follows a passing complete test run.
- Preserve bb MIT notice and license in source and built application.

## Review Focus

- Multiple content blocks, interleaved thinking/text and final snapshots must retain ordering without duplicated text.
- Stop/crash must not leave tool rows permanently marked running.
- Existing transcripts without IDs or structured tool arguments must remain readable.
- Expanding a long card must keep the reader at that card; streamed updates still follow the bottom.
- Markdown code and model-supplied HTML must remain inert; opening a link requires an explicit click.

**Interfaces:** `Timeline(messages, redact)` updates the existing transcript list via `event(event)`; `restore_messages(messages, redact)` projects Pi session messages. Entries carry stable `id`, role, text and optional tool metadata/status.
