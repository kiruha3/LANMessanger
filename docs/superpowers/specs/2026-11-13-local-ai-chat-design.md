# Локальный агент Pi в LAN Messenger

## Назначение

Добавить чат с локальным ИИ-агентом в существующее приложение Python 3.11 / PyQt6. Пользователь подключает аккаунт или API-ключ провайдера и задаёт задачу во вкладке «ИИ». Агент автоматически получает папку приложения и права текущего пользователя: читает и меняет файлы, запускает команды. Пользователь уточнил, что отдельный выбор папки не нужен и весь сценарий должен находиться внутри вкладки «ИИ»; детали ниже — предлагаемая реализация.

## Подходы

Рекомендуемый вариант — отдельный процесс Pi через `--mode rpc`, связанный с PyQt через JSONL в stdin/stdout. Pi ведёт цикл модели и инструментов, приложение отвечает за интерфейс, определение каталога приложения и жизненный цикл процесса. SDK Pi для всего агентского цикла потребовал бы дополнительного Node-моста, а собственный цикл на Python дублировал бы готовый harness. Отдельный небольшой помощник для входа по аккаунту допустим, если он нужен для встроенного сценария авторизации. Серверный агент TechHelper исключён выбором пользователя: выполнение должно быть локальным.

Из TechHelper используем как образец разделение подключения модели, выполнения, событий и состояния чата. Django, Agent Manager и серверную БД в LAN Messenger не переносим.

## Интерфейс и сценарий

- Вкладка «ИИ» в главном окне объединяет весь сценарий: список агентских чатов, историю, многострочное поле ввода, отправку, остановку и настройки подключения. Отдельное агентское приложение или терминал пользователю для общения не требуются.
- Рабочую папку определять автоматически при запуске приложения и показывать её абсолютный путь. Для portable exe на Windows это папка, содержащая sys.executable; для запуска из исходников — начальный os.getcwd(). Для macOS .app — папка, содержащая сам bundle .app. Не использовать временную папку распаковки PyInstaller или Application Support как рабочую папку агента. Это конкретизация исполнителя требования «папка, где открыто приложение».
- Выбор или подтверждение папки перед первым сообщением не нужны; отдельного выбора каталога для каждого чата нет.
- Настройки подключения во вкладке: провайдер, модель, вход по аккаунту либо API-ключ; для совместимого API — адрес сервера и модель.
- Показывать поступающий текст, вызовы инструментов и их результаты, ошибки и состояние выполнения. Не показывать внутреннее рассуждение модели как обязательную часть ответа.
- На время ответа запрещать повторную отправку в том же чате. Команда «Стоп» отменяет текущую задачу; новая отправка становится доступна после подтверждения остановки или завершения процесса.
- Папку фиксировать на время запуска. Если после переноса приложения сохранённый чат относится к другой папке, историю сохранять, а для нового каталога создавать новую агентскую сессию; незаметно продолжать прежнюю сессию в другом каталоге нельзя.

## Локальный runtime

Первая реализация использует установленный Pi; путь к нему можно указать в настройках. На исследованной машине Node и npm есть, Pi в PATH не найден. Начальная проверяемая версия пакета `@mariozechner/pi-coding-agent` — 0.73.1, требование Node — >=20.6.0. Закрепить реально проверенную версию в инструкции установки.

Pi запускается через QProcess без видимого окна консоли, с `workingDirectory`, равным автоматически определённой папке приложения. Читать stdout как UTF-8 JSONL, разделяя только по LF и сохраняя неполный кадр между чтениями. stderr обрабатывать отдельно; сообщения протокола не смешивать с диагностикой. UI обновляется в главном потоке Qt.

Один процесс обслуживает одну открытую агентскую сессию. Одновременное выполнение в нескольких чатах в первой версии не требуется. Открытие другого чата во время задачи блокируется с предложением сначала остановить задачу. При обычном закрытии окна в трей задача продолжает работать; при полном выходе приложение останавливает свой процесс Pi. Порядок abort, ожидания и принудительного завершения определить по проверенному RPC-контракту.

Если runtime отсутствует или не запускается, показывать понятную ошибку и инструкцию установки; LAN-чаты продолжают работать. В первую версию не входит упаковка Node/Pi внутрь portable exe. При разработке проверить требования Pi к командной оболочке на Windows и включить их в диагностику.

## Аккаунты и ключи

Для аккаунта использовать поддерживаемый самим Pi вход и его хранилище авторизации. Вход начинается кнопкой во вкладке «ИИ»; ссылку, код и состояние авторизации показывать там же. Если провайдер требует браузер, открывать его страницу входа, затем возвращать результат во вкладку. Ручной запуск pi и ввод /login в отдельном терминале не являются готовым пользовательским сценарием. При необходимости использовать небольшой Node-помощник на API авторизации Pi; точный контракт проверить перед реализацией. После входа приложение повторно проверяет доступные модели. Пароль провайдера в интерфейсе мессенджера не собирается. Конкретный набор доступных подписок определяется проверенной версией Pi и провайдером.

API-ключ передавать дочернему процессу через отдельное окружение, не через аргументы командной строки. Для сохранения ключа использовать платформенное хранилище учётных данных; при его отсутствии оставлять ключ только в памяти до выхода. Не записывать ключи в settings.json, историю сообщений и диагностические логи. Поддержать один активный профиль подключения; каталог из нескольких профилей можно добавить позднее.

## Доступ и передача контекста

Папка задаёт рабочий каталог и контекст, но не служит песочницей. По запросу пользователя агент действует с обычными правами его учётной записи, включая доступ за пределами каталога. Приложение не повышает привилегии и не добавляет повторных подтверждений каждого инструмента.

Внешний провайдер получает запрос и содержимое, которое Pi передаёт модели при выполнении задачи. Определение рабочей папки само по себе не должно загружать весь каталог. При входе в режим агента кратко объяснить, что обработанные моделью данные уходят выбранному провайдеру. Переписка LAN, комнаты и их история автоматически в контекст не добавляются.

## Сессии и хранение

Хранить метаданные ИИ-чатов отдельно от peer-чатов: идентификатор чата, заголовок, абсолютный каталог, провайдер, модель и ссылку на файл сессии Pi. Данные размещать в каталоге приложения по существующим правилам base_dir(). Использовать явный файл сессии для каждого чата; одинаковая рабочая папка не должна объединять разные чаты.

Источником контекста агента служит сохранённая сессия Pi. Приложение хранит представление сообщений и инструментов для восстановления интерфейса; при запуске проверяет согласованность с сессией. После аварийного завершения не отправлять прежний запрос повторно автоматически: показать прерванное выполнение и разрешить явное продолжение.

## Область первой версии

Включены текстовый агентский чат во вкладке «ИИ», автоматическая рабочая папка приложения, встроенный сценарий входа по аккаунту или ключу, выбор модели, вывод инструментов, остановка и восстановление сессии. MCP, изображения, агент в групповой комнате, серверная синхронизация ИИ-истории и сборка exe в эту задачу не входят. Эти границы предложены исполнителем и могут быть изменены пользователем.

## Проверка

Проверить процессный адаптер управляемым фиктивным RPC-процессом: разрезанные UTF-8/JSONL-кадры, несколько событий в одном чтении, ошибка команды, остановка, аварийный выход и отсутствие повторного исполнения после восстановления. Проверить определение каталога для исходников, portable exe и .app, включая запуск ярлыком с другой cwd и исключение временного каталога PyInstaller. UI-проверка должна покрыть автоматическую папку, вход по аккаунту или ключу во вкладке, отправку, потоковый текст и завершение процесса при выходе.

Прогнать полный существующий набор через `py -3.11 scripts/run_tests.py`. Живой запрос модели выполнять только с доступным авторизованным подключением; при его отсутствии отдельно сообщить, что реальный провайдер не проверен. Для ручного теста инструментов использовать временную папку и простую задачу создания и чтения файла.

При реализации обновить CHANGELOG.md, README.md, вкладку «Помощь» и затронутые инструкции. Если сборка exe будет заказана отдельно, поднять версию, повторить обязательные проверки и проверить запуск собранного процесса. Пуш и публикация не входят в задачу.

## Основания

- TechHelper: `backend/core/tasks/agent_manager_bridge.py` — Pi среди поддерживаемых движков, передача LLM-подключения и агентского контекста.
- TechHelper: `frontend_shadcn/src/types/chatRuns.ts`, `src/http/chatRuns.ts` — состояния, отмена, события и восстановление выполнения.
- LAN Messenger: `app/ui/main_window.py`, `app/ui/chat_window.py`, `app/core/history.py` — точки подключения интерфейса и правила локальных данных.
- Метаданные и README npm-пакета Pi: RPC для интеграций вне Node, аккаунты и ключи, сессии, стандартные инструменты read/write/edit/bash.
